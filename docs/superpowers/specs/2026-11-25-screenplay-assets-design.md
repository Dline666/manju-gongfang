# 剧本顺带产出资产 · 设计稿

日期：2026-11-25
状态：已实现
关联需求：「从小说生成剧本到剧本生成分镜这部分的内容，我需要一个更好的方案来保证下游生成视频时获得的提示词更精准」

用户拍板：

1. **生成剧本时，JSON 输出里同时带上三类资产**（人物 / 场景 / 道具）。
2. **提取规则由用户自己写**，写在模板提示词里；系统只提供块位。
3. **分镜阶段按剧本生成的需要字段来产**，能引用剧本阶段给出的资产。

前序设计：`2026-11-25-director-storyboard-design.md`（分镜改由导演步骤调模型结构化）

---

## 1. 意图与背景

上一轮把分镜改成「导演步骤调模型结构化产出」，链路变成：

```
写剧本（只出文本） → 导演分镜（模型结构化出镜头） → 资产（从镜头提取） → 分镜 → 视频
```

但视频提示词的精准度上不去，根因有三个：

- **分镜产出时还不知道有哪些资产**。流程上资产排在导演之后，所以导演写 `visual` 时只能写「少年在雨夜山门拾起一把断剑」这种叙事描述，写不出「阿青（灰白旧布衣、背空剑鞘）蹲在青灰石阶上」。
- **资产固定短语和动作是两张皮**。视频提示词里固定短语是一份孤立清单，模型得自己猜谁在动。
- **视频提示词漏了两项**：镜头的 `visual`（画面）与 `start`（开场）根本不在视频提示词里，只有动作、运镜、终点。

---

## 2. 目标 / 非目标 / 反目标

### 目标

- G1 剧本步骤一次调用同时产出**剧本文本 + 三类资产清单**。
- G2 剧本给出的资产直接落进 `project.assets`，id 稳定、可被分镜按 id 引用。
- G3 分镜每镜能声明**在场的资产**与**谁是主体**，模型按 id 引用，不靠名字猜。
- G4 导演提示词带**本片资产清单**（id + 品类 + 名称 + 固定短语），画面描述能直接嵌进固定短语。
- G5 视频提示词补上**画面**与**开场**，主体资产单独标出。
- G6 提取规则与出图约定都由用户自己写，系统只给块位。

### 非目标

- N1 不动资产提取步骤（`extract-characters` / `extract-scenes` / `extract-props`）的功能与入口：它仍然可以从镜头里补出剧本没写的道具。
- N2 不改生图、视频、导出链路。
- N3 不做分镜版本历史。
- N4 不改后端契约之外的任何业务规则。

### 反目标

- A1 **提取规则与出图约定不能混在一起**。出图约定（「3D风格」「纯白背景」「正面站立全身」）进了资产固定短语就会逐字进视频提示词，把视频模型带偏——它会真的把角色画成白底全身站姿。两类文案必须分开放。
- A2 **系统不替用户编造规则**。出厂模板里的每一句都是用户自己提供的，可在模板编辑器里改或删；系统不生成任何规则文案。
- A3 **模型给的资产 id 必须跨调用稳定**。分镜按 id 引用，id 变了引用就断。
- A4 **同名资产不能被模型覆盖用户手改过的固定短语**。

## 3. 数据流

```
小说 / 主题
   │  一次模型调用
   ▼
剧本步骤 ──► { title, logline, screenplay, assets: { characters, scenes, props } }
   │                        │
   │                        └──► 落地成 project.assets（id 沿用模型的）
   ▼
导演步骤 ──► 每镜带 assets: [{ assetId, role }] + sceneId
   │        输入 = 剧本正文 + 本片资产清单
   ▼
资产步骤（仍可从镜头补道具）+ 逐镜挂载
   ▼
视频提示词 = 画面 + 开场 + 承接 + 附件顺序 + 动作运镜终点 + 对白 + 固定资产块（主体标注）+ 风格
```

## 4. 剧本步骤

### 4.1 后端契约

`SCREENPLAY_SCHEMA`（`functions/handler.ts`）多一个 `assets`：

```jsonc
{ "title": "…", "logline": "…", "screenplay": "…",
  "assets": {
    "characters": [{ "id": "c1", "name": "沈砚", "aliases": "小砚，砚儿", "description": "沉默寡言", "lock": "十七岁少年，灰白旧布衣，背空剑鞘" }],
    "scenes":     [{ "id": "s1", "name": "山门", "lock": "青灰石阶九十九级，晨雾低垂" }],
    "props":      [{ "id": "p1", "name": "断剑", "lock": "红绳缠绕的剑柄，断口有微弱金色灵光" }]
  } }
```

- `lock` = **固定短语**，逐字复用，是资产与画面之间唯一的事实来源。
- `aliases` 按用户要求用逗号分隔的字符串，前端拆成数组存进 `Asset.aliases`。
- `description` 放补充描述（人物是性格），`fixedDescription` 仍是 `lock || description`。

### 4.2 校验

`validateScreenplayAssets`：**坏条目跳过，不让整份剧本作废**。剧本才是这一步的主产出，资产是附带的；一条资产写坏了不该让用户重付一次。

### 4.3 前端落地

`normalizeScreenplay` 现在返回资产（`src/features/script/creation.ts` 的 `screenplayAssets`）：

- **id 沿用模型给的**（分镜要按它引用）；缺失或组内重复时用「品类前缀 + 序号」兜底（`c1` / `s1` / `p1`）。
- 同名同类的已有资产**保留它自己的 id 与固定短语**（用户手改过的不被模型覆盖），只有空白占位才补上。
- `mergeDraftAssets` 同步做了这条规则。

## 5. 分镜步骤

### 5.1 后端契约

`DIRECTOR_SCHEMA` 每镜多两个字段：

```jsonc
"sceneId": "s1",
"assets": [{ "assetId": "c1", "role": "subject" }]
```

`role` 三值：`subject`（画面主体）/ `background`（背景）/ `prop`（道具）。坏条目（缺 assetId）跳过，不让整次导演请求失败。

### 5.2 前端落地

`normalizeDirector`：

- `assets` 按 id 映射到 `shot.assetIds`；`role === 'subject'` 的进 `shot.subjects`。
- 引用了不在资产表里的 id → **丢掉并计数**（`DirectorResult.unknownAssets`），导演页弹提示。
- `sceneId` 有效 → 把场景资产也算进本镜在场，场景描述才和资产库对得上。
- **说话人按名字或代称挂到人物资产上**（`characterByName`），视频提示词才写得出人名。

### 5.3 导演提示词

`DATA_SOURCES.director` 多一个数据源 `director.assets`（标题「本片资产清单」）：

```
c1 · 人物 · 沈砚 —— 十七岁少年，灰白旧布衣，背空剑鞘
s1 · 场景 · 山门 —— 青灰石阶九十九级，晨雾低垂
p1 · 道具 · 断剑 —— 红绳缠绕的剑柄，断口有微弱金色灵光
```

这是**作品数据**（系统注入），不是规则文案。模型据此写画面描述，把固定短语嵌进去。

---

## 6. 视频提示词

`DATA_SOURCES.video` 多一个 `video.visual`（标题「画面与开场」），排在 `video.heading` 之后：

```
画面：沈砚蹲在石阶下，指尖抠开泥。
开场：石阶下
```

`shotAssetText` 给主体资产加标注：`人物「沈砚」（主体）：十七岁少年，灰白旧布衣`。

## 7. 模板

### 7.1 新增块位

剧本栏多三个内置块（标题按现有「人物 · 识别规则」的写法带前缀，group 也沿用）：

- `script.characters.extract`「人物 · 提取规则」
- `script.scenes.extract`「场景 · 提取规则」
- `script.props.extract`「道具 · 提取规则」

### 7.2 出厂全局模板

`defaultSettings.promptTemplates`（`src/domain/types.ts` 的 `defaultPromptTemplates`）出厂带六块，**每一句都是用户自己提供的**：

| 位置 | 块 | 内容 |
|---|---|---|
| 剧本栏 | 人物 · 提取规则 | 年龄、性别、发色、发型、脸部特征、上/下装、鞋子、身高；代称逗号分隔；着装互不相同；不用表格 |
| 剧本栏 | 场景 · 提取规则 | 场景名 + 描述；只写环境建筑器物光线氛围；不出现人物；同一「所属空间」归并 |
| 剧本栏 | 道具 · 提取规则 | 道具名 + 描述；只写形制材质尺寸颜色纹理磨损；同一道具合并；无形制可标「需设计」 |
| 图片栏 | 人物三视图条款 | 正面站立全身形象图；「3D风格」；纯白背景；手中不拿道具 |
| 图片栏 | 场景构图说明 | 干净空镜场景图，不出现人物 |
| 图片栏 | 道具构图说明 | 干净单一道具展示图，背景简洁中性 |

**出图约定单独放图片栏**，不进资产提取规则 —— 见反目标 A1。

`migrateSettings` 里 `promptTemplates: migrateTemplateSet(saved.promptTemplates) ?? base.promptTemplates`：存档里没有全局模板时用出厂那份；用户自己删空后保存的是 `{ templates: {} }`，不会被出厂值覆盖。

## 8. 校验与提示

- `scriptWarnings`（`src/domain/flow.ts`）：资产名在剧本正文里没出现 → 提示「可能是模型编出来的」。只提示不阻断。
- `DirectorResult.unknownAssets`：分镜引用了不存在的资产 id → 导演页弹提示。

## 9. 验收

### 单元

- 剧本三类资产落地：id 沿用、代称拆开、坏条目跳过、重复 id 换新。
- 同名资产并入时保留用户改过的固定短语。
- 分镜按 id 引用 → `assetIds` / `subjects`；不存在的 id 计数。
- 说话人按名字或代称挂到人物资产。
- 导演提示词带资产清单（id + 固定短语）。
- 视频提示词带画面、开场、主体标注。
- 出厂模板：六块齐全；出图约定不进资产提取规则。
- 后端契约：剧本 schema 有 `assets`，导演 schema 有 `assets` / `sceneId`；坏资产条目被跳过。

### 浏览器（Edge 1440 / 390）

- 剧本生成后资产库出现人物 / 场景 / 道具，数量与提示一致。
- 导演分镜后每镜显示「在场资产」。
- 视频提示词含画面与开场。

### 命令

- `npm test`（235 项）、`npm run build`、`npx tsc --noEmit`、`deno check functions/index.ts` 全绿。
- 13 条浏览器回归全绿。
