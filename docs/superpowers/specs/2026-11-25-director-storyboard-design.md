# 分镜改由导演步骤调模型结构化 · 设计稿

日期：2026-11-25
状态：已实现
关联需求：「分镜处理有问题，生成剧本后不要自动拆镜，在导演分镜步骤再调用大模型来结构化输出需要的分镜脚本，同样，默认提示词模板暂时不需要，分镜数量可根据剧本自动调节」

用户拍板两件事：

1. **流程顺序调换**：剧本 → 导演分镜 → 资产 → 分镜 → 视频。
2. **导演步骤重跑时全部替换旧镜头**（不做镜号对齐的增量合并）。

---

## 1. 意图与背景

现状（第三轮改造之后）：

- 剧本步骤产出完整 Markdown 剧本后，由**前端正则解析器** `parseScreenplay`（`src/features/script/screenplay.ts`）按「【镜头：类型】」标记切段，产出 `project.shots`。
- 资产步骤从**这份镜头**里提取人物 / 场景 / 道具，并逐镜挂载资产。
- 导演步骤再调一次大模型，但只补景别、运镜、机位、开场、动作、终点 —— **镜数必须与既有镜头严格一致**（`normalizeDirector` 校验 `data.shots.length !== project.shots.length` 就报错）。

问题：

- 正则解析器不理解剧本，只会按标记切段。剧本写得自由一点（没有【镜头：类型】、或一个标记里塞了两件事），拆出来就是碎的、错的。
- 镜数由解析器决定，不是按剧本内容决定。
- 「人物三视图」这类设定图规则和镜头结构混在同一份提示词里。

用户要求：**剧本只出剧本；分镜由导演步骤调大模型结构化产出；镜数按剧本自动调节；这一步暂时不需要默认提示词模板。**

---

## 2. 目标 / 非目标 / 反目标

### 目标

- G1 剧本步骤只产出一份剧本正文，**不拆镜、不写 `project.shots`**。
- G2 导演步骤读剧本正文，调大模型输出**完整的分镜脚本**：场景、画面、时长、景别、运镜、机位、开场、动作、终点、对白。
- G3 **镜数由模型按剧本内容决定**，后端不再要求与既有镜头一致。
- G4 导演步骤重跑 = **整体替换**旧镜头，不做镜号对齐的增量合并。
- G5 流程顺序改为 **剧本 → 导演分镜 → 资产 → 分镜 → 视频**。
- G6 导演步骤**不需要任何默认提示词模板**：模板为空也能跑（提示词 = 用户块 + 剧本正文 + 附加 Skill；后端契约始终随请求发送）。

### 非目标

- N1 不改生图、视频、导出链路。
- N2 不做分镜版本历史与回滚。
- N3 不新增付费调用，仍是一次模型调用。
- N4 不改资产提取的品类拆分与逐镜挂载机制（只是它上游的镜头来源变了）。

### 反目标（做了就算失败）

- A1 **剧本步骤不得再写 `project.shots`**，也不得用解析器的结果兜底。
- A2 **不得为导演步骤预置任何默认提示词文案**——系统不预置默认文案是本项目的既定原则。
- A3 **不得让模型改写剧本里的对白**：对白必须逐字来自剧本。
- A4 **不得让导演步骤写资产**：资产仍由资产步骤负责，导演步骤不碰 `project.assets`。

## 3. 流程重排

### 3.1 新顺序

```
写剧本  ──►  导演分镜  ──►  建资产  ──►  做分镜  ──►  生成视频
（只出剧本）  （模型结构化出镜头）  （从镜头提取并逐镜挂资产）
```

调整点：

| 位置 | 原 | 新 |
|---|---|---|
| 1 | 写剧本（出剧本 **+ 拆镜**） | 写剧本（只出剧本） |
| 2 | 建资产（从镜头提取） | **导演分镜**（从剧本结构化出镜头） |
| 3 | 导演分镜（从镜头补运镜） | 建资产（从镜头提取，逐镜挂载） |

`src/domain/flow.ts` 的 `flowStages` 改成 `['script', 'director', 'assets', 'storyboard', 'video']`，`stageRequirement` 跟着改成 `director ← script`、`assets ← director`、`storyboard ← assets`。

`src/App.tsx` 的侧边栏与顶部步骤条按 `navigation` 数组渲染，把「建资产」与「导演分镜」两项对调。

### 3.2 为什么资产步骤留在导演步骤之后

资产步骤的输入就是镜头列表（`extract.*.shots` 数据源），并且逐镜挂载也按镜号对齐。把导演步骤放到它前面，资产步骤**一行代码都不用改**，而且提取的输入从「正则拆出来的镜头」换成「模型结构化出来的镜头」——认人、认景、认道具的准确度只会更高。

反过来（保持原顺序）就得让资产步骤改成从散文剧本里认资产，再把逐镜挂载挪到导演步骤，职责两头都挪。

### 3.3 各步状态判定

| 步 | 判定 |
|---|---|
| 剧本 | 剧本正文非空 |
| 导演分镜 | 有镜头，且每镜齐备（画面、时长、景别运镜、开场、动作、终点） |
| 资产 | 有资产（沿用现状） |
| 分镜 | 资产已确认且 `storyboardReady` |
| 视频 | 同上 |

指纹（`scriptFingerprint` / `directorFingerprint`）跟着改：

- **剧本指纹**改为对剧本正文 + 主线取哈希（原来是对镜头取哈希，而镜头已经不属于剧本步骤了）。
- **导演指纹**扩到镜号、画面、时长、景别运镜、开场、动作、终点、对白。

## 4. 剧本步骤：只出剧本

### 4.1 产出物

`normalizeScreenplay(input)` 改成只返回 `{ title, logline, screenplay }`：

- 不再解析镜头。
- 不再抛「剧本里没有找到可拆镜的内容」——没有镜头就没有拆镜失败这回事。
- 剧本正文为空仍然报错。

`templateScript(theme)`（模板演练）同样只产出剧本。

`parseScriptText(input)`（导入剧本）改成把原文当作剧本正文存下来；不再按镜号解析、不再产出镜头。

### 4.2 界面

- 「保存并重新拆镜」→「**保存剧本**」。
- 统计从「N 场 · M 镜 · X 秒」改成「**N 字 · M 场**」（场数按剧本里的「### 场景N」计数）。
- 帮助文案：「保存时会自动拆成镜头」改成「镜头由下一步的导演分镜用模型结构化产出」。
- 「确认并进入下一步」跳到**导演分镜**。
- 剧本步骤不再显示时长表（`DurationStrip` 是按镜头算的，等导演步骤产出镜头后才有意义）。

### 4.3 校验

`validateScriptStage` 改为：剧本正文不能为空、长度在合理区间。不再检查镜号、时长、资产关联（那些属于导演步骤）。

## 5. 导演步骤：模型结构化出分镜

### 5.1 提示词

数据源（`DATA_SOURCES.director`）从「逐镜脚本」换成「剧本正文」：

| 数据源 | 内容 |
|---|---|
| `director.screenplay` | 剧本正文全文 |
| `director.skills` | 附加 Skill（storyboard 阶段） |

用户块（模板）照旧可选。**不预置任何默认文案**：模板为空时，提示词 = 剧本正文 + 附加 Skill，后端契约（`DIRECTOR_SCHEMA`）始终随请求发送——结构要求写在 schema 的字段描述里。

### 5.2 后端契约

`DIRECTOR_SCHEMA`（`functions/handler.ts`）扩成完整的分镜结构：

```ts
shots: [{
  number,            // 镜号，从 1 连续
  title?,            // 镜标题
  scene,             // 场景头，如「外景 · 山门 — 清晨」
  visual,            // 画面：只写看得见的东西，不写景别与运镜
  duration,          // 本镜时长（秒）
  shotSize,          // 远景/全景/中景/近景/特写
  movement,          // 固定/推/拉/摇/移/跟/升降/环绕
  angle,             // 平视/俯视/仰视
  start, action, end,
  dialogues: [{ speaker, text, emotion? }],
}]
```

- **镜数**：`minItems: 1, maxItems: 100`，由模型按剧本内容决定；不再有「必须等于既有镜数」的约束。
- **对白逐字**：`text` 的字段描述写明「逐字照抄剧本原句，不改写、不增删」。
- **景别**：`shotSize` 的字段描述写明「剧本里有【镜头：类型】时按它落实」——剧本里的标记仍然有用，从「切镜依据」降级成「景别提示」。

### 5.3 前端落地

`normalizeDirector(input, project)` 从「合并进既有镜头」改成「**按模型输出重建镜头列表**」：

- 镜号按返回顺序重排为 1..N（模型返回的 number 只用来校验连续性）。
- 每镜生成新的 `Shot`：`duration`、`visual`、`camera`（`景别·运镜·机位`）、`start` / `action` / `end`、`scene`、`title`。
- 对白：模型给的文本先到**剧本对白池**里核对（见 5.4），命中就用剧本原文，未命中才保留模型文本并计数。
- 说话人先只记名字（`speakerId` 留空），等资产步骤建出人物资产后再按名字挂上 —— 与现在的做法一致。
- `assetIds` / `references` 一律清空：资产是下一步的事（G4 / A4）。

### 5.4 对白逐字保护

剧本步骤的产物是剧本正文，导演步骤的产物要带对白。模型重述对白有改写风险，所以前端做一次核对：

1. 从剧本正文里扫出对白池：`{ speaker, text }[]`（逐行匹配「名字（情绪）：台词」）。
2. 模型给的每句对白按说话人 + 文本（去空白后）在池里找。
   - 命中 → 用**剧本原文**（哪怕模型改了标点或多打了字）。
   - 未命中 → 保留模型文本，计数。
3. 计数 > 0 时在导演页面提示「有 N 句对白与剧本原文不一致，请核对」。

这样「对白逐字来自剧本」这条约束不依赖模型自觉。

### 5.5 界面

- 空状态从「先完成剧本 → 导演步骤需要剧本里拆出的全部镜头」改成「先完成剧本 → 导演步骤需要剧本正文」。
- 「AI 生成分镜（先确认）」的弹窗描述改成：发送剧本正文，产出完整分镜脚本；镜数由模型按剧本决定。
- 卡片展示新增「场景」与「画面」两行（现在只有景别/运镜、动作）。
- 「确认并进入下一步」跳到**资产**。
- 「本地补全」保留：给缺景别/开场/动作/终点的镜头补上默认值。

### 5.6 离线「模板演练」（后补，不属于用户原始要求）

流程重排后暴露一个问题：本项目一直承诺「没有 Key 也能用模板演练走完整条流程」，重排后剧本步骤只出剧本，**没有 Key 的用户会卡在导演步骤**——AI 生成要 Key，剧本步骤又不再拆镜。

因此补一条**显式、非 AI** 的离线路径：

- **入口在导演页**，新增「模板演练（本地）」按钮；已有镜头时先弹确认框再整体替换。它是主动动作，不是自动拆镜：剧本生成后什么都不做，只有人点这一下才会排。
- **排法很死**（`src/features/script/creation.ts` 的 `rehearseShots`）：
  - 按空行分段，一段一镜；剧本里写了 `【镜头：类型】` 的段落按标记落实景别（`远景·固定·平视`、`跟拍` → `中景·跟·平视`、`俯拍` → `中景·固定·俯视`）。
  - 场景名取最近的一个 `### 场景N`；没有场景头时用「未标注场景」。
  - 时长照抄剧本里的「（时长Ns）」，一个段落里有多个就加起来；没有就按台词长度估（每段至少 3 秒）。
  - 对白按「名字（情绪）：台词」拆出来。
- **结构说明不排进镜头**：「核心前提 / 黄金3秒钩子 / 节拍表」这些段落不是戏，遇到第一个场景头之前的内容一律不进镜头。
- **排出来的就是正式分镜**：每镜都有场景、画面、时长、景别运镜、开场、动作、终点，能直接通过 `validateDirectorStage`，可以逐镜手改后确认进入资产步骤。模板剧本演练后排 14 镜、总时长 28 秒。

## 6. 资产步骤

**逻辑不变**：

- 数据源仍是 `extract.*.shots`（镜头列表）。
- 逐镜挂载仍按镜号对齐。
- 差别只有一个：镜头现在由模型产出，格式与之前一致（`number` / `visual` / `dialogues` / `assetIds`）。

入口门禁跟着流程重排走（进入资产需要导演步骤已完成）。

界面文案里「从剧本提取资产」改为「从分镜提取资产」——输入现在是镜头。

---

## 7. 迁移

**不需要存档迁移。**

- 旧作品里的 `project.shots` 继续可用；导演步骤重跑时整体替换。
- 旧作品里没有 `project.screenplay` 的（很早期的手工项目），导演步骤会提示「还没有剧本正文」。
- 字段层面没有任何新增或删除，`Shot` / `Project` 的形状不变。

## 8. 验收

### 单元

- `normalizeScreenplay`：只返回剧本，不产出镜头；空剧本报错；不再抛拆镜失败。
- `normalizeDirector`：按模型输出重建镜头；镜数与旧镜头数无关；镜号重排为 1..N；对白与剧本原文对齐；未命中的对白被计数。
- `rehearseShots`：按剧本结构排镜；结构说明不进镜头；时长照抄标记；排出的镜头能通过导演步骤校验。
- 流程：`stageStatus` / `canEnter` 按新顺序放行；剧本指纹覆盖剧本正文；导演指纹覆盖分镜字段。
- 提示词：导演提示词只带剧本正文，不带镜头 JSON。

### 浏览器（Edge 1440 / 390）

- 剧本生成后**没有镜头**：资产步骤不可进入，导演步骤可进入。
- 导演步骤产出 N 镜（N 由模型给），剧本页与导演页显示一致。
- 导演步骤重跑，镜数变了也能跑（旧镜头整体被替换）。
- 资产步骤从新镜头提取，逐镜挂载正常。
- 空模板也能跑导演步骤（不需要默认提示词模板）。
- 没有 Key 时点「模板演练（本地）」也能排出镜头并继续往下走。

### 命令

- `npm test`（227 项通过）、`npm run build`、`npx tsc --noEmit`、`deno check functions/index.ts` 全绿。
- 既有 13 条浏览器回归脚本全绿（流程顺序变了，`browser-flow.mjs`、`browser-assets.mjs`、`browser-prompt-edit.mjs`、`browser-recovery.mjs`、`browser-models.mjs`、`browser-endpoints.mjs` 都跟着改了）。

## 9. 未验证

- 真实收费 API 端到端未跑；模型结构化分镜的实际质量未验收。
- 剧本正文很长时，导演提示词可能超出 32000 字上限——本轮不做截断策略。
- 对白核对的「相似匹配」只做精确与去空白匹配，不做语义相似度判断。
